# 2026-07-13 m-context Reusable Agent Context

## Source

- Source: Codex chat
- Date: 2026-07-13

## Request Text / Source-preserving Summary

The user identified that the `m-*` workflow lacks a reusable external context store. They want to save context once, then load it alongside another skill, for example:

```text
$m-test $m-context nas配置
```

The named context may contain several Markdown sections. The agent should load the requested context before running the consuming skill so the user does not need to repeat NAS paths, credentials, commands, or other operational details.

The user explicitly allows plaintext secrets such as passwords and keys. The purpose is convenient Agent automation on the trusted local machine; encryption and external secret-manager integration are not required.

## Context

- Context data must be separate from the skill package so it can change without reinstalling the skill.
- The default store should live outside Git repositories.
- The Agent is allowed to read the complete plaintext context, including secrets.
- Markdown headings provide progressive, section-level loading.

## Confirmed Requirements

- Add a standalone `$m-context` skill that composes with other `$m-*` skills.
- Store plaintext Markdown context files under a user-level context root.
- Resolve a named context deterministically and load it before co-invoked skills.
- Support loading an entire context or one named section.
- Support listing and finding available contexts.
- Permit plaintext passwords, tokens, private keys, and similar sensitive values.
- Avoid repeating sensitive values in the final response unless the task requires it.

- None blocking for the first version.
