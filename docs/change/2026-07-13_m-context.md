# 2026-07-13 m-context Reusable Agent Context

## 变更背景 / 目标

Users had to repeat stable environment details, paths, commands, and credentials in every Agent task. This workflow added a reusable plaintext context store and a composable `$m-context` loader so named context can be loaded before another `m-*` skill acts.

## 具体变更内容

- Added the `skills/m-context` package, UI metadata, Markdown format reference, and install manifest.
- Added a standard-library Python loader supporting root discovery, list, find, exact whole-file load, and exact Markdown section load.
- Allowed plaintext passwords, tokens, private keys, and other secrets as intentional Agent-readable context.
- Added Unicode handling, fenced-code-aware heading parsing, duplicate-heading failures, Windows filename validation, traversal rejection, and resolved-root escape protection.
- Exposed `$m-context` from the `m-autoflow` collection as a context-first companion rather than a workflow phase.
- Added focused unit and CLI regression coverage.
- Validated and synchronized both `m-context` and the changed `m-autoflow` package into the local Codex skills installation.

## 经验 / 教训摘要

- Personal operational context should remain separate from skill distribution so users can change secrets and environment facts without reinstalling a skill.
- Exact filename and heading matching avoids silent use of the wrong environment or credential set.
- Markdown section parsing must ignore fenced code because private keys and command examples can contain heading-like text.
- Replace-style skill synchronization requires a pre-sync drift check and an exact post-sync parity check.

## 可复用排查线索

- Symptoms: `$m-context` cannot find a context; a requested heading is ambiguous; Windows symlink escape test is skipped; installed-skill hashes differ unexpectedly.
- Trigger conditions: missing `M_CONTEXT_HOME`/`CODEX_HOME`, filename mismatch, duplicate Markdown headings, Windows account without symbolic-link privilege, CRLF/LF conversion.
- Keywords / errors: `Context root does not exist`, `Context not found`, `Section is ambiguous`, `WinError 1314`, `客户端没有所需的特权`, `exact_parity`, `ignore-space-at-eol`.
- Quick checks: run `context_loader.py root`; run `context_loader.py list`; inspect exact headings; check Windows Developer Mode or privilege before symlink tests; compare installed files with line-ending-tolerant diff before sync.

## 关键设计决策与权衡

- Chose one user-level Markdown root instead of project/global shadowing in version one.
- Chose plaintext direct Agent readability because the user explicitly values automation convenience over encryption complexity.
- Chose a deterministic standard-library helper instead of instruction-only filesystem reads so errors, section boundaries, Unicode, and path validation remain consistent.
- Kept `$m-context` outside the staged phase chain so it can compose with `$m-test`, `$m-quick`, or other skills without changing workflow state.

## 潜在影响

- Selected contexts are intentionally visible to the Agent and task session, including plaintext secrets.
- A malformed or missing context now blocks dependent work rather than allowing guessed configuration.
- Residual validation risk: the symlink/junction escape fixture could not run on the current Windows account, though the resolved-root guard is implemented and the test remains available on capable environments.
